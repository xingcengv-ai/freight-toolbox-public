# 项目结构说明

## 先看哪里

日常维护只需要看以下三个位置：

```text
src/        Vue 和 TypeScript 源码
local-resources/  本机私有资源（Git 会整体忽略）
docs/       中文设计说明
```

下面这些是自动生成或第三方代码，不需要阅读和修改：

```text
dist/          npm run build 生成的压缩代码
node_modules/  npm install 下载的第三方依赖
package-lock.json 依赖版本锁定文件
```

`dist/assets/*.js` 看起来像编译代码是正常的，它是给浏览器或未来 EXE 运行的，不是开发源码。

## 源码目录

```text
src/
├── main.ts                         Vue 程序启动入口
├── App.vue                         主页面、公司切换、单票查询、Excel 导入
├── styles.css                      全站页面样式
├── types.ts                        数据类型定义
├── components/
│   └── BatchQuote.vue              批量粘贴和批量结果表
├── assets/
│   └── templates/                  可公开的空白导出模板
└── services/
    ├── companyStore.ts             公司和报价版本的独立存储
    ├── importerRegistry.ts         公司解析器注册表
    ├── excelImporter.ts            当前报价格式的 Excel 解析器
    └── rateQuery.ts                统一报价查询函数
```

## 一个公司一个报价库

程序中的存储结构为：

```text
CompanyRateStore
└── companies[]
    ├── 我的公司
    │   ├── parserId: LCL_SOUTH_V1
    │   ├── activeDatasetId
    │   └── datasets[]
    │       ├── 0810报价
    │       └── 0820报价
    └── 其他公司
        ├── parserId: UNCONFIGURED
        └── datasets[]
```

导入 Excel 时只更新当前选中的公司。其他公司的报价不会被清除或参与查询。

## 为什么每家公司要有解析器

Excel 的 Sheet 名、表头位置、计费阶梯和备注格式可能不同，因此不能使用一个固定解析器强行处理全部公司。

每增加一种格式，需要：

1. 在 `src/services/` 新增该公司的解析器。
2. 在 `importerRegistry.ts` 注册解析器。
3. 给公司设置相应 `parserId`。
4. 用该公司的真实 Excel 做回归测试。

查询层只读取统一的 `RateDataset`，不需要知道原 Excel 长什么样。

## 当前数据保存在哪里

当前网页测试版把公司和标准化报价保存在浏览器的 `localStorage` 中，键名为：

```text
freight-toolbox-company-rate-store-v2
```

这适合第一阶段本机测试。以后打包 Tauri Windows EXE 时，建议将它换成应用数据目录里的 SQLite 或 JSON 文件，源码中的查询和解析结构可以继续使用。

## 私有报价文件放在哪里

真实报价表、参考表格以及依赖真实价格的验证资料统一放在项目根目录的 `local-resources/` 中。这个目录已被 Git 整体忽略，不会上传到公开仓库。可公开的导出模板只保留表头和格式，存放在 `src/assets/templates/`。

## 常用命令

```bash
npm run dev      # 启动开发版，修改源码后自动刷新
npm run build    # 生成 dist 生产文件
npm run preview  # 预览生产文件
```
